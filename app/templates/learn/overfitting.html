The same problem in logistic regression

{% if model and model.validation.optimism_unpenalized %} {% set o = model.validation.optimism_unpenalized %}

Even an unpenalized logistic regression with {{ model.features|length }} predictors fits too closely: on the training data it has AUC {{ "%.2f"|format(o.auc.apparent) }}, but the bootstrap estimates it would fall to {{ "%.2f"|format(o.auc.corrected) }} on new patients, with calibration slope {{ "%.2f"|format(o.cal_slope.corrected) }} (a slope below 1 means predictions that are too extreme).

{% endif %}

Penalized logistic regression uses cross-validation to choose how far to "pull" the weights towards zero: when the signal is weak it takes them almost to zero (as happened with the obese patients), when there is signal it keeps them but softens them. Practical rules:

  • before choosing the algorithm, count the events (Riley's criteria);
  • always evaluate on patients the model has not seen, and check calibration as well as AUC;
  • a neural network is justified only with many events and interacting predictors; on small tabular data penalized logistic regression is usually just as good and easier to explain.
